# 퍼그랑 · PUG DAYS

퍼그를 키우는 작은 웹게임입니다. **Vercel은 웹페이지와 게임 API를 실행하고, Supabase는 진행 데이터를 보관합니다.** Vercel 서버의 임시 파일이나 브라우저 localStorage에 게임 진행을 저장하지 않습니다.

제공한 코드는 배포 준비가 된 소스입니다. 실제 Vercel/Supabase 계정을 연결하거나 공개 배포한 상태는 아닙니다. 로컬 검사와 화면 확인을 마쳤으며, 실제 Supabase 연결 및 Vercel 배포 검증은 아래 설정 후 진행해주세요.

## 1. 먼저 내 컴퓨터에서 해보기

1. ZIP을 압축 해제합니다.
2. [Node.js 공식 사이트](https://nodejs.org/)에서 **Node.js 24**를 설치합니다.
3. Windows에서는 `START-DEMO.cmd`를 실행합니다.
4. 브라우저에서 `http://localhost:3000`을 엽니다.

터미널에서 실행하려면 압축을 푼 폴더에서:

```powershell
$env:LOCAL_DEMO="1"
node server.mjs
```

별도 npm 패키지 설치는 필요 없습니다. 로컬 데모는 `.local/saves/`에 JSON 파일로 저장합니다. 창을 닫거나 서버를 재시작해도 이 폴더와 브라우저 쿠키가 남아 있으면 이어집니다. 이 파일 저장 방식은 개발 체험용이며 Vercel에서는 사용할 수 없도록 막았습니다.

로컬 서버는 이 컴퓨터에서만 접근할 수 있도록 설정돼 있습니다. 종료는 터미널에서 `Ctrl+C`입니다. 이미 실행 중이면 같은 서버를 다시 시작하지 말고 열린 주소를 이용하세요.

## 2. Supabase 데이터베이스 만들기

1. [Supabase](https://supabase.com/dashboard)에 로그인하고 **New project**로 프로젝트를 만듭니다. 프로젝트 이름은 자유롭게 지정합니다.
2. 프로젝트의 **SQL Editor**에서 `supabase/schema.sql` 파일 전체를 붙여넣고 **Run**을 누릅니다.
3. **Project Settings → Data API** 또는 프로젝트 연결 정보에서 **Project URL**을 찾습니다. 예: `https://xxxxxxxx.supabase.co`.
4. **Settings → API Keys**에서 **Secret key**(`sb_secret_...`)를 확인합니다. 기존 키 체계를 쓰는 프로젝트는 서버용 `service_role` 키도 지원합니다. `anon` 또는 publishable 키는 이 서버에 사용할 수 없습니다.

이 키는 데이터베이스 접근 권한이 있으므로 **Vercel 서버 환경변수에만** 넣습니다. GitHub, `public/app.js`, HTML 또는 채팅에 붙여넣지 않습니다. Supabase 주소 자체는 비밀이 아니지만 키는 비밀입니다.

SQL은 `pug_saves` 테이블을 만들고 RLS를 활성화하며, 일반 브라우저 클라이언트의 읽기·쓰기를 차단합니다. 게임 서버가 비밀 키로만 읽고 쓰는 구조입니다. Supabase Auth 로그인 설정이나 이메일 발송 설정은 필요 없습니다.

이 프로젝트는 Supabase HTTPS Data API를 사용하므로 DB 비밀번호·Postgres 접속 문자열·커넥션 풀 설정은 필요 없습니다.

## 3. 코드를 GitHub에 올리기

1. [GitHub](https://github.com/new)에서 저장소를 만듭니다. 비공개 저장소여도 됩니다.
2. 압축을 푼 **프로젝트 안의 파일들**을 올립니다. 저장소 최상단에 `package.json`, `vercel.json`, `api/`, `public/`이 보여야 합니다. ZIP 파일 하나만 올리면 배포되지 않습니다.
3. `lib/`, `scripts/`, `supabase/`, `tests/`, `server.mjs`, README도 함께 올립니다.
4. `.env.local`, 비밀 키, `.local/`의 개인 저장 파일은 올리지 않습니다. `.gitignore`에 제외 규칙을 넣었습니다. GitHub 웹 업로드를 쓰는 경우에는 직접 제외해주세요.

중첩 폴더째 업로드했다면 다음 단계에서 Vercel의 **Root Directory**를 `package.json`이 들어 있는 폴더로 지정하면 됩니다.

## 4. Vercel에 배포하기

1. [Vercel](https://vercel.com/new)에 로그인합니다.
2. **Add New → Project**에서 방금 만든 GitHub 저장소를 가져옵니다.
3. 설정을 확인합니다.

| 항목 | 값 |
|---|---|
| Framework Preset | Other |
| Root Directory | `package.json`이 있는 프로젝트 폴더 |
| Node.js Version | 24.x |
| Build Command | `node scripts/check.mjs` |
| Output Directory | `public` |

`vercel.json`에 빌드 명령과 출력 폴더가 설정돼 있습니다. 별도의 프런트엔드 빌드나 의존성 설치가 필요하지 않습니다. Vercel이 `api/game.js`를 Node.js 서버 함수로 처리합니다.

4. **Environment Variables**에 다음 두 값을 추가합니다. 우선 Production에 적용하고, Preview 배포도 테스트하려면 Preview에도 적용합니다.

| 변수 이름 | 값 |
|---|---|
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SECRET_KEY` | `sb_secret_...` 비밀 키 또는 기존 `service_role` 키 |

`LOCAL_DEMO`는 Vercel에 등록하지 않습니다. 이 두 변수 이름에 `NEXT_PUBLIC_` 같은 공개 접두사를 붙이지 않습니다.

5. **Deploy**를 누릅니다. 완료되면 `https://프로젝트이름.vercel.app` 형태의 주소가 생성됩니다.
6. 환경변수를 나중에 수정했다면 **Deployments → Redeploy**로 재배포합니다.

Vercel은 페이지/API 실행을 담당하고, 저장 데이터는 Supabase에 남습니다. 코드 배포를 반복해도 같은 Supabase 프로젝트·테이블을 쓰면 진행이 유지됩니다. 운영용과 테스트용 데이터를 분리하려면 별도 Supabase 프로젝트를 사용하세요. 서비스별 무료 플랜 제공 범위·휴면·사용량 조건은 가입 시 해당 서비스의 최신 안내를 확인하세요.

## 5. 배포 후 확인하기

1. 배포 주소를 열고 퍼그 이름을 짓습니다. 상단이 **서버에 저장됨**인지 확인합니다.
2. 밥을 한 번 주고 새로고침합니다. 이름, 친밀도, `1 / 3` 표시가 유지돼야 합니다.
3. **저장 / 불러오기 → 내 복구 코드 확인**에서 코드를 안전한 곳에 보관합니다.
4. 다른 브라우저나 기기에서 같은 배포 주소를 열고, 첫 이름 화면의 **불러오기**로 복구 코드를 입력합니다. 같은 퍼그가 나타나야 합니다.
5. 새로운 브라우저 프로필 또는 시크릿 창에서 이름을 `똥퍼그`로 입력합니다. 치트 안내와 새 이름 입력창이 나타나고, 새 이름으로 시작하면 친밀도 100이어야 합니다.

### 저장과 복구 방식

- 회원가입 없는 **개인별 저장**입니다. 각 브라우저에 충분히 긴 무작위 세션 키를 HttpOnly 쿠키로 저장하고, 서버 DB에는 그 키의 SHA-256 해시와 게임 진행을 저장합니다.
- 복구 코드는 해당 퍼그에 접근할 수 있는 비밀번호와 같습니다. 다른 사람에게 공유하지 마세요.
- 같은 기기의 같은 브라우저는 자동으로 이어집니다. 쿠키 삭제, 시크릿 창 종료, 기기 변경, 도메인 변경 시에는 복구 코드가 필요합니다.
- 복구 코드 없이 쿠키까지 지우면 기존 퍼그를 다시 찾을 수 없습니다. 계정 기반 이메일 복구는 이 버전에 포함하지 않았습니다.
- 다른 퍼그를 불러오면 현재 브라우저 연결만 바뀝니다. 이전 퍼그의 DB 데이터는 삭제되지 않으며, 이전 복구 코드로 돌아갈 수 있습니다.
- 로컬 데모의 복구 코드는 로컬 저장소에만 통합니다. 로컬 진행을 Supabase로 옮기는 자동 마이그레이션은 포함하지 않았습니다.

## 게임 규칙

사용자가 지정하지 않은 수치는 아래와 같이 설정했습니다. 수정은 `lib/game.mjs`의 `RULES`, `createState`, `chance`를 기준으로 하고, 화면 설명도 함께 바꾸세요.

| 행동 | 횟수 | 친밀도 / 결과 |
|---|---|---|
| 이름 정하기 | 시작 시 1회, 1~12자 | 이름 저장, 모든 행동 메시지에서 이름으로 부름 |
| 밥 주기 | 한국 시간 하루 3회 | 매회 +5 |
| 산책 | 횟수 제한 없음 | 하루 첫 2회 각각 +8 |
| 쓰다듬기 / 엉덩이 / 배 | 횟수 제한 없음 | 세 행동 합산 하루 첫 5회 각각 +3 |
| 주둥이 말랑말랑 | 횟수 제한 없음 | 애니메이션과 기록. 친밀도 보상 없음 |
| 훈련 | 하루 5회, 실패도 1회 사용 | 선택한 개인기 성공 시 습득 |
| 배운 개인기 시켜보기 | 횟수 제한 없음 | 훈련 횟수 사용 없이 애니메이션 재생 |

첫 산책에서는 코랄·민트·하늘·라일락·노랑 중 목줄 색을 선택합니다. 색은 서버 저장 데이터에 포함되어 다음 접속과 다른 기기에서 복구한 뒤에도 유지됩니다. 이전 버전 저장도 첫 산책 때 색을 고를 수 있습니다. 별도 DB 스키마 변경은 필요 없습니다.

산책 중에는 공원 배경, 움직이는 나무·산책로, 선택한 색의 목줄과 리드줄, 네 다리가 교차하는 둥근 옆모습이 표시됩니다. **걷기 / 달리기** 버튼으로 속도를 바꿀 수 있습니다. 달리기는 다리 움직임, 몸의 도약, 배경 이동이 더 빠릅니다. **집으로 돌아가기**를 누르거나 체력이 0이 될 때 산책을 마칩니다. 한 번 출발할 때만 산책 횟수·친밀도 보상을 계산하며, 속도 전환은 보상을 추가하지 않습니다. 산책 중 다른 돌봄과 훈련은 귀가 후 할 수 있습니다.

### 산책 발견과 친구

실제로 산책한 누적 시간 **30초마다** 서버가 한 번 추첨합니다. 아이템 발견 35%, 친구 강아지 만남 25%, 별일 없음 40%입니다. 속도를 바꾸거나 귀가·재출발해도 같은 구간을 다시 추첨하지 않으며, 체력이 소진된 뒤의 시간은 포함하지 않습니다.

발견 시 고슴도치 인형·뼈다구·솔방울·깃털·네잎클로버·하트 돌멩이·비스킷 가운데 하나를 고릅니다. 물건 6종은 **상점에서 구매할 수 없는 도감 전용 수집품**으로, 발견 횟수와 첫 발견 날짜를 저장합니다. 비스킷은 1~3개를 지갑에 바로 넣으며 도감에 포함하지 않습니다. 중복 발견도 횟수로 남습니다. 친구는 두부 또는 밤이이며 약 12초 동안 마주 보고 꼬리를 흔들며 노는 장면을 보여줍니다.

창을 닫아 둔 동안 발견한 물건도 도감과 기록에 남으며 지난 장면을 한꺼번에 재생하지 않습니다. 일반 산책은 체력 제한까지 계산하고, 장기간 닫아 둔 치트 산책은 한 번 정산할 때 최근 240구간까지만 처리합니다.

### 체력과 잠자기

체력은 0~100이며 새 게임은 100으로 시작합니다. 기존 저장에는 진행을 유지하면서 체력 100을 추가합니다. 친밀도 시작값 0과는 별개입니다.

| 행동 | 체력 변화 |
|---|---|
| 걷기 | 5초마다 −1 |
| 달리기 | 2초마다 −1 |
| 새 개인기 훈련 | 성공·실패 모두 −12 |
| 밥 | +20, 기존 하루 3회 제한 적용 |
| 쓰다듬기·엉덩이·배 | 매회 +5, 친밀도 보상 횟수와 별도 |
| 잠자기 | 초당 +2, 100이 되면 자동으로 일어남 |
| 배운 개인기 시켜보기 / 주둥이 만지기 | 체력 변화 없음 |

체력이 0이면 자동으로 집으로 돌아오고, 체력이 12 미만이면 훈련할 수 없습니다. **잠자기** 버튼으로 회복하고 **기지개 켜고 일어나기**로 중간에 깨울 수 있습니다. 자는 동안에는 다른 돌봄을 하기 전에 깨워야 합니다. 치트모드에서는 산책·훈련으로 체력이 줄지 않습니다.

체력·산책 속도·수면 상태·목줄 색은 모두 서버에 저장합니다. 서버가 지난 시간을 계산하므로 새로고침하거나 브라우저를 닫아도 소모·회복을 우회할 수 없습니다. 다시 열면 아직 진행 중인 산책이나 수면을 이어서 보여주고, 이미 체력이 소진되었거나 전부 회복되었다면 종료된 상태로 표시합니다. 활성 화면은 체력을 매초 표시하고 서버와 약 5초마다 동기화합니다. 체력 소진/회복 완료 시에는 바로 동기화를 요청합니다. 네트워크가 끊겼을 때는 재연결 후 서버의 최종 상태를 반영합니다.

엎드려는 앞발을 내밀며 배를 낮추고, 빵야는 옆으로 쓰러져 눈을 감고 발을 들며, 일어서는 뒷발로 서서 앞발로 균형을 잡습니다. 훈련 성공 시와 습득한 개인기를 눌렀을 때 모션을 약 6초 보여줍니다. OS의 모션 줄이기 설정을 사용하면 움직임 대신 해당 자세를 보여줍니다.

- 일반 모드 초기 친밀도는 **0**, 최댓값은 **100**입니다. 기존에 저장한 퍼그의 친밀도는 그대로 이어집니다.
- 훈련 개인기는 **엎드려, 빵야, 일어서, 손**입니다. 이미 배운 개인기는 다시 훈련하지 않습니다.
- 실제 성공 확률은 `15 + 친밀도 × 0.8` 퍼센트입니다. 친밀도 0→15%, 20→31%, 50→55%, 100→95%. 화면에는 정수로 반올림해 표시합니다.
- 성공 판정은 서버의 암호학적 난수로 합니다. 브라우저가 친밀도, 성공 여부, 횟수를 지정할 수 없습니다.
- 일반 모드에서 전날 **밥·산책·쓰다듬기** 중 한 번도 하지 않은 항목마다 **−3**입니다. 셋 다 하지 않으면 하루 **−9**이며 0 아래로는 내려가지 않습니다. 밥 3회를 모두 채워야 감소를 면하는 규칙은 아닙니다.
- 엉덩이·배 만지기는 쓰다듬기 실적에 포함됩니다. 주둥이 만지기는 포함되지 않습니다.
- 날짜 경계는 브라우저 시간대와 무관하게 **Asia/Seoul 자정**입니다. 접속하지 않은 날의 감소는 다음 서버 요청 때 한꺼번에 정산합니다. 별도 스케줄러가 필요 없습니다.
- 퍼그 이름을 아직 정하지 않은 상태에는 방치 감소가 없습니다. 이름을 정한 날부터 돌봄 날짜가 시작됩니다.
- 이름 입력창에 **`똥퍼그`**를 입력하면 서버가 치트모드로 초기화하고 이름 입력창부터 다시 진행합니다. 새 이름을 입력하면 **친밀도 100, 밥·훈련 무제한, 훈련 성공률 100%, 방치 감소 없음**으로 플레이합니다. 치트모드 자체도 저장됩니다.
- 모든 모드에서 과도한 연속 요청을 막는 350ms 간격 제한이 있습니다.

## 퀘스트 · 옷장 · 집중 동행

게임 화면 위의 **퀘스트와 옷장 링크** 또는 방 아래의 새 영역에서 시작합니다.

| 성장 퀘스트 | 목표 | 한 번 받는 보상 |
|---|---|---|
| 우리, 가족이 되자 | 누적 밥 1번 + 쓰다듬기 3번 | 복숭아 조끼 + 비스킷 10 |
| 같이 걷는 길 | 실제 산책 누적 2분 | 바다 줄무늬 옷 + 비스킷 15 |
| 너는 작업, 나는 응원 | 집중 동행 누적 5분 | 별빛 잠옷 + 비스킷 15 |
| 우리 집 재주둥이 | 훈련 또는 배운 개인기 10번 | 라일락 니트 + 비스킷 20 |
| 든든한 작업 친구 | 집중 동행 누적 25분 | 비스킷 30 |

**오늘의 미션**은 밥 1번+쓰다듬기 3번(비스킷 10), 산책 1분(15), 집중 동행 10분(20)입니다. 한국 시간 자정에 진행도와 수령 여부가 초기화됩니다. 일일 보상은 당일에 받아주세요. 성장 퀘스트의 누적 진행과 보유 의상·비스킷은 날짜가 바뀌어도 유지됩니다. 산책은 버튼을 누른 횟수가 아닌 실제 진행 시간으로 계산하며, 체력이 떨어진 시점까지만 인정합니다.

완료 카드에서 **선물 받기**를 누르면 옷과 비스킷이 저장됩니다. 선물 창에서 바로 입히거나 **옷장 → 입히기**로 장착하고 같은 버튼으로 벗습니다. 집·산책·개인기·수면·집중 동행의 퍼그 몸에 의상이 적용됩니다. **비스킷 상점**에서 의상 10종을 비스킷 18~200개로 교환할 수 있습니다. 현금 결제나 무작위 뽑기는 없습니다.

**함께 작업 시작하기**를 누르면 집중 동행을 시작합니다. 퍼그가 공놀이(18초) → 책 읽기(22초) → 쉬기(12초)를 반복합니다. 공을 굴릴 때 앞발과 고개가 함께 움직이고, 책을 읽을 때는 안경을 쓰고 책장을 넘깁니다. 입고 있는 옷은 각 자세에 맞춰 유지됩니다. 새로고침해도 동행 시작 시간에 맞는 장면으로 돌아오며, 동행을 마치면 소품이 사라집니다. 기기의 동작 줄이기 설정을 켜면 반복 모션을 멈춥니다. 체력은 기존과 같이 20초마다 1씩 회복합니다. 누적 5분마다 비스킷 1~2개가 선물함에 쌓이며 **선물 받기**로 지갑에 옮깁니다. 다른 탭이나 창을 닫은 동안에도 서버의 경과 시간으로 계산됩니다. 한 번 시작한 동행은 최대 4시간 뒤 자동 종료되며, 비스킷 48~96개가 쌓입니다. 중간에 동행을 마쳐도 아직 5분을 채우지 못한 진행은 다음 동행에 이어집니다. 다시 시작하면 새로 최대 4시간 동안 진행합니다. 단순히 게임을 열기만 해서는 적립되지 않습니다.

동행 중에는 돌봄·산책·훈련 대신 **동행 마치고 같이 놀기**를 눌러 복귀합니다. 퀘스트 보상 수령과 옷 갈아입기는 동행 중에도 가능합니다. 서버에서 경과 시간과 보상 수령을 검증하고 저장하므로 새로고침, 재시도, 여러 탭으로 같은 보상을 중복 수령할 수 없습니다. 별도 타이머 서버나 스케줄러 없이 다음 요청 때 경과 시간을 정산합니다.

기존 저장은 v4로 자동 확장하며 이름·친밀도·체력·개인기·목줄은 유지합니다. 업데이트 시 남아 있는 당일 밥·쓰다듬기·훈련 횟수는 성장 퀘스트에 인정합니다. 과거에 기록하지 않았던 산책 시간과 집중 시간은 업데이트 이후부터 누적합니다. Supabase의 JSON 상태 안에 저장하므로 SQL 스키마 변경 없이 코드를 다시 배포하면 됩니다. 로컬에서는 실행 중인 서버를 재시작해야 합니다.

### 상점과 방치 보상 밸런스 (v4)

퀘스트 보상 의상 4종과 비스킷 상점 의상 10종, 총 14종을 모을 수 있습니다. **옷장**에는 퀘스트 의상과 소유한 옷을, **비스킷 상점**에는 구매 가능한 옷을 보여줍니다.

| 상점 의상 | 비스킷 가격 |
|---|---:|
| 새싹 조끼 | 18 |
| 딸기우유 땡땡이 | 30 |
| 피크닉 체크 | 45 |
| 구름 산책복 | 60 |
| 꿀벌 티셔츠 | 80 |
| 딸기 정원 | 95 |
| 숲속 탐험복 | 110 |
| 퍼그 락커 조끼 | 130 |
| 작은 청멜빵 | 150 |
| 밤하늘 별셔츠 | 200 |

새 집중 동행은 **5분당 1~2개 / 시간당 12~24개 / 한 동행 최대 4시간·48~96개**입니다. 각 5분 구간에서 1개와 2개가 같은 확률로 정해지며, 새로고침 횟수에 따라 보상이 바뀌지 않습니다. 방치 보상만으로 첫 상점 옷을 사려면 45~90분이 필요하고, 일일 미션을 모두 완료하면 추가로 45개를 얻습니다. 상점은 부족한 비스킷 수를 보여줍니다. 별도의 구매 보너스나 수익 배수 의상은 없어 먼저 산 옷 때문에 보상 속도가 계속 빨라지지 않습니다.

기존 지갑·선물함·소유 의상은 보존합니다. 업데이트 이전에 시작한 동행은 첫 접속 때 이미 지난 시간을 이전 보상률로 한 번 정산하고, 이후 구간부터 5분당 1~2개로 전환합니다. 동행을 다시 시작할 필요는 없습니다. 옷은 각 자세의 몸통 윤곽 안에 맞추고, 앉기·걷기의 앞다리와 엎드린 자세에는 소매를 추가했습니다. 옷을 입을 때 기본 스카프는 숨겨 목 부분이 겹치지 않게 했습니다.

### 장난감과 가구

**비스킷 상점 → 장난감 / 가구**에서 구매합니다. 테니스공 24개, 삑삑 오리 42개, 로프 60개, 버섯 조명 65개, 구름 방석 80개, 미니 록 스피커 95개, 작은 책장 110개입니다. 책장은 바닥에 닿는 3단 크기로, 전등은 반대편에 크게 배치됩니다. 구매하면 정해진 자리에 바로 배치되며 **치우기 / 놓기**로 보관과 재배치를 할 수 있습니다. 소유권과 배치는 서버에 저장되고, 중복 구매는 차단됩니다.

집중 동행의 놀이 시간마다 꺼내 둔 장난감을 순서대로 선택합니다. 테니스공은 굴리기, 오리는 누르고 튀기기, 로프는 당기기 동작으로 놉니다. 사용 중인 장난감은 바닥에서 잠시 빠졌다가 놀이가 끝나면 제자리로 돌아갑니다. 모두 치우면 기존 기본 공으로 놀며, 가구와 장난감은 보상 속도를 바꾸지 않습니다. 산책 중에는 방의 물건을 표시하지 않습니다. 스피커가 놓여 있으면 놀이와 독서 사이에 18초 동안 리듬 타기 장면이 추가됩니다. 퍼그가 고개와 앞발을 흔들고 스피커의 진동판과 음표가 움직입니다. 실제 오디오 재생은 포함하지 않습니다. 락커 조끼는 검은 몸판·실버 스터드·사선 지퍼로 꾸몄고, 집·산책·개인기 자세별로 몸에 맞춰 표시합니다.

### 글꼴과 오늘의 행운

제목·주요 버튼·행운 메시지에는 주아체를 사용합니다. 원본 글꼴과 SIL Open Font License를 `public/fonts/`에 포함하여 외부 글꼴 서버에 연결하지 않습니다. 출처: [Google Fonts Jua](https://github.com/google/fonts/tree/main/ofl/jua).

왼쪽의 **오늘의 행운**은 서버의 한국 날짜로 선택하는 31개 메시지입니다. 같은 날에는 새로고침·다른 기기에서도 같으며, 자정 이후 다음 메시지로 넘어갑니다. 켜 둔 화면은 최대 30초 안에 날짜를 확인하고, 다시 열린 탭도 서버에서 갱신합니다. 메시지는 `lib/fortune.mjs`에서 편집할 수 있습니다.

## 코드 구조

```text
api/game.js           Vercel API: 세션, 이름, 행동, 복구, 서버 난수
lib/game.mjs          순수 게임 규칙 / 한국 날짜 / 친밀도 / 훈련
lib/progression.mjs   퀘스트 / 의상 목록 / 집중 동행 경과 시간과 보상
lib/exploration.mjs   산책 발견 / 친구 만남 / 도감
lib/store.mjs         Supabase 저장 / 충돌 처리 / 로컬 데모 저장
public/index.html    한국어 게임 UI + SVG 퍼그
public/style.css     반응형 레이아웃 + 행동 애니메이션
public/app.js        화면 갱신 / API 요청 / 오류·재시도 / 복구 UI
public/journey.js    퀘스트 카드 / 옷장 / 집중 동행 타이머
supabase/schema.sql  DB 테이블 및 접근 권한 설정
server.mjs           로컬 개발 서버
scripts/check.mjs    배포 시 구문·필수 파일 검사
tests/               게임 규칙 / 동시 저장 / HTTP 세션 검사
vercel.json          Vercel 배포 설정 + 보안 헤더
```

Supabase 레코드의 `revision`을 조건으로 갱신하는 낙관적 잠금을 사용합니다. 여러 창에서 같은 저장 데이터를 변경해도 충돌한 요청은 최신 상태를 읽고 다시 계산합니다. 네트워크 재시도는 동일 요청 ID로 처리하며 유효 시간 동안 중복 차감을 방지합니다. 저장을 확인하지 못하면 성공한 것처럼 표시하지 않고 재시도를 안내합니다.

```powershell
node --test tests/*.test.mjs
node scripts/check.mjs
```

Supabase를 로컬에서 연결해 테스트하려면 `.env.example`을 `.env.local`로 복사하고 실제 두 값을 설정한 뒤 실행합니다.

```powershell
node --env-file=.env.local server.mjs
```

## 퍼그와 단어 공부

- 단어장 버튼에서 UTF-8 TXT 파일을 올립니다. 한 줄에 `단어 뜻`을 넣으며 첫 띄어쓰기(여러 칸·탭 포함)만 구분자로 사용합니다. 뜻 안의 띄어쓰기와 쉼표는 그대로 보존합니다. 단어 자체가 여러 낱말이면 `"look up" 찾아보다`처럼 큰따옴표로 감쌉니다. 기존 쉼표 구분 파일도 읽을 수 있습니다.
- 파일당 256KB, 저장 단어 최대 1,000개입니다. 빈 줄은 건너뛰고 같은 단어·뜻 조합은 중복 저장하지 않습니다. 형식 오류가 있으면 줄 번호를 안내하고 파일 전체를 저장하지 않습니다. 추가 업로드는 기존 단어장에 합쳐집니다.
- 검색, 수정, 삭제를 지원합니다. 진행 중이거나 일시정지된 공부가 있으면 먼저 마치거나 그만둔 뒤 단어장을 수정합니다.
- 목표는 저장한 단어 수 이내에서 1개부터 정합니다. 중복 없이 무작위로 뽑아 왼쪽 단어 4개·오른쪽 뜻 4개를 표시합니다. 맞힌 카드가 새 카드로 바뀌고 마지막에는 남은 개수만 표시됩니다. 같은 뜻 또는 같은 철자가 여러 개 있어도 유효한 짝을 인정합니다.
- 지식은 0으로 시작합니다. 하루에 처음 맞힌 단어·뜻 조합당 0.5 오르고 최대 100입니다. 틀린 답은 지식을 깎지 않습니다. 같은 날 같은 단어를 다시 맞히거나 삭제 후 다시 올려도 중복 지급하지 않습니다.
- 한국 시간으로 하루 동안 정답이 없으면 다음 접속/요청 시 지식 3을 차감합니다. 여러 날 비우면 누적 차감하며 최소 0입니다. 기존 저장 데이터에 기능이 처음 추가되기 전의 날짜는 소급 차감하지 않습니다.
- 한 쌍을 맞힐 때마다 서버가 정답을 판정하고 진행과 지식을 저장합니다. 일시정지·중간 종료에서도 획득한 지식은 유지됩니다. 새로고침 후 진행 중이던 카드/일시정지 상태를 이어갑니다. 학습 중에는 산책·수면·집중 동행과 중복 진행하지 않습니다.
- 단어장·지식·학습 세션은 기존 `pug_saves.state` JSONB에 저장하므로 별도 SQL이나 환경변수를 추가할 필요가 없습니다. 기존 세션 쿠키/복구 코드로 플레이어별로 구분합니다. 다른 기기는 같은 사이트에서 복구 코드로 연결하면 같은 단어장을 사용할 수 있습니다.
- UI 텍스트는 HTML로 삽입하지 않습니다. 요청 크기와 단어 길이를 서버에서 제한하며, 저장 충돌 및 요청 재시도는 기존 revision/receipt 보호를 사용합니다.

### 이번 기능의 검증

로컬 브라우저에서 TXT 업로드, 단어 수정, 4쌍 매칭과 카드 보충, 오답 처리, 6개 목표 완료와 지식 3 증가, 일시정지 후 새로고침 복원을 확인했습니다. 자동 검사에는 서버 판정, 일일 지식/감소 경계, 중복 지급 방지, 단어 CRUD, 파일 오류/상한, 저장 재개, 동시 요청, 실제 HTTP 업로드 및 세션 격리를 포함합니다. 공개 Vercel 사이트에 반영하려면 업데이트된 전체 소스를 기존 프로젝트로 배포해야 합니다.

## 탭과 지식 퀘스트

돌보기 / 단어 공부 / 퀘스트·상점을 상단 탭으로 분리했습니다. 공부 카드는 단어 공부 탭에서만 보입니다. 탭 전환은 공부를 종료하지 않으며 주소에 선택한 탭을 기록해 새로고침 후에도 유지합니다. 방향키와 Home/End 키로 탭을 선택할 수 있습니다.

공부 퀘스트는 최고 지식 10·30·60·100 달성 시 각각 비스킷 10·20·35·50개를 한 번 지급합니다. 지식 30 달성 보상으로 꼬마 학사모도 받습니다. 달성 기록은 지식이 감소해도 유지됩니다. 학사모는 옷장의 별도 모자 슬롯에 저장돼 기존 옷과 동시에 착용하거나 벗을 수 있으며, 공부·돌보기·산책·개인기에서 퍼그 머리를 따라갑니다. 새 장비/기록도 기존 서버 저장 JSON에 포함되어 별도 SQL은 필요하지 않습니다.
